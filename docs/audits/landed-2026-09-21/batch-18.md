# Landed-work audit, batch 18 (forge, tasks 778-794)

This batch's task list names only 778, 781, 782, 784, 787, 789, 790, 792,
793 and 794; the other numbers in the 778-794 range are not part of this
batch. Every landing here is a `Merge main into …` commit, but the two
parents are not always in the order the task text implies: for several of
these (782, 787, 789, 792, 794) the branch actually being landed had
forked from a sibling task's not-yet-landed branch, so `<landed>^2` (the
literal second parent) sometimes names the *older* main state rather than
the branch's own tip. In each such case the branch's own tip was found by
matching its one-line commit summary against the task's own wording (for
example task 787's own commit is titled "presence: reset CPUQuota to
infinity when a transition's quota is unset", found as the first parent,
not the second), and the diff below is against that tip, or against the
common ancestor when the tip carries a sibling task's work forked in
underneath it (787, 792). 778, 781, 784, 790 and 793 are plain
non-merge or ordinary-order merges and needed no such correction. All
tests named below were run individually on 2026-09-28 against the current
tree (606e3b2) and passed; `tests/file_size.rs` and `tests/fn_length.rs`
also pass on the current tree.
