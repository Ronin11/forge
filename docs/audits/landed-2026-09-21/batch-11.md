# Landed-work audit, batch 11 (forge, tasks 626-638)

This audit checks each task's landed change against its own text. Most of
the landed commits here are `Merge main into …` merges; their own change
was read as `git diff <landed>^2 <landed>`, since the merge commit's first
parent is the task's own branch and the second parent is `main` — that
diff is what the branch itself added. The non-merge landings (634's
`8c4ba49e980d`, 635's `003b38e4fd30`, 636's `6f06bac649d7`, 637's
`9b2408dd1512`, 638's `2eb5c41a20b7`) were read as `git diff <base>
<landed>`. Three of the task texts (635, 636, 638) are themselves a
supervisor's one-fix-one-test instruction on top of an earlier attempt
that had already landed on the same branch; their `<base>` already
includes that earlier attempt, so the diff shown for them covers both.

Several pieces have moved since landing: `src/engine.rs`'s continuation
logic for task 638 is now in `src/engine/step/continuation.rs` and
`src/engine/step.rs`; `src/job.rs`'s `recover_interrupted` for task 626 is
now in `src/job/recovery.rs`; task 627's `Sandbox` for provider state now
supports more than one agent shape. One finding below (task 627) is about
documentation that went stale after a later, unaudited task (628,
`f144e7f92bb7`, landed between 627 and 629) changed the behaviour 627's
own docs describe, without updating them.

Only the tests each task named, or their current successors, were run,
with `bwrap` present at `/usr/bin/bwrap`, so the sandboxed tests really
ran. All of them passed on 2026-10-03 against this tree.
