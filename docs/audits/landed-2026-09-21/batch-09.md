# Landed-work audit, batch 09 (forge, tasks 603-613)

This audit checks each task's landed change against its own text. Every
landing in this batch is a `Merge main into …` commit, so its own change
was read as `git diff <landed>^2 <landed>` (the branch's own work relative
to where main stood at merge time); for 605 and 606 that work actually
spans two non-merge commits each (fixup commits on the same branch), so
the range is `git diff <base> <landed>` against the two branch commits
together, which is what `<landed>^2 <landed>` also shows. Each change was
then traced on the current tree (96d5841). Only the tests each task named
(or their current successors, when a later split moved them) were run,
all on 2026-09-28 against this tree; all of them passed.

Several tasks in this range land in a different order than their numbers
suggest — 608's own branch was forked from main before 603 landed, for
example — so a file one task's text describes as "not yet a crate" can
already hold that crate on the current tree once a sibling branch landed
first. That is noted where it shows up (608's evidence) rather than
counted against either task.
