# Landed-work audit, batch 17 (forge, tasks 738-775)

This audit checks each task's landed change against its own text. Six of
the nine landings are `Merge main into …` merges, so their own change was
read as `git diff <landed>^2 <landed>` (main's tip merged in is the second
parent, so this diff shows the branch's own commits net of the merge, the
same set `git log --first-parent` back to the base would list). The three
non-merge landings (92e1c3a673ee task 740, e4ccd12a3ca4 task 744,
79c91808d231 task 775) and task 770's landing (c90d5803f734, itself not a
"Merge main into …" commit, so its own base-to-landed diff already includes
its earlier commits on the branch, including the merge `bd95718` it made of
the current base) were read as `git diff <base> <landed>`.

Each change was then traced on the current tree (606e3b2). Two modules
were split up by later, unrelated work: `src/landing.rs` gained
`src/landing/round.rs` (the base-push retry loop) and `src/landing/effects.rs`
(the post-lock side effects, including the assess call); `src/engine.rs`
gained `src/engine/worktree.rs` and `src/engine/land.rs`; `src/job.rs`
gained `src/job/recovery.rs`, whose `prepare_run` now gives each job run
its own `run-<n>` subdirectory instead of task 762's `archive_prior_input`
renaming a single directory aside — a strictly more thorough version of
the same guarantee (no run's `effects.log` is ever truncated or lost).
`src/egress.rs` gained `src/egress/tests.rs` and moved the proxy
directories from a fixed `forge-egress-<pid>` name directly under
`std::env::temp_dir()` to a per-euid `run_root()` with `egress-<pid>`
underneath, again preserving task 770's rules (own directory removed only
at exit, a startup sweep of dead pids only, doctor counting what it swept)
under a hardened path. `src/git.rs` gained `src/git/tests.rs`. None of
these moves changed the behaviour the tasks asked for.

Only the tests each task named, or their current successors, were run —
each with `forge-test --fresh cargo test --workspace <name>` (`forge-test`
without a trailing filter runs the declared `[checks].test`, and with one
runs exactly that binary and args, so a bare test name has to be handed to
`cargo test` explicitly). All ran on 2026-09-28 against this tree and all
passed.
